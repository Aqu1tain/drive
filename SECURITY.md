# Security

## Reporting a vulnerability

Please do not open a public issue. Use the **Security → Report a vulnerability** tab of the GitHub repository (private report), or write to [contact@corentinrenard.com](mailto:contact@corentinrenard.com). Include the version, the steps to reproduce and the estimated impact. You will get an answer as soon as possible.

## Security model

- A single owner account; every other account is a reader. A reader cannot perform any write operation on files, folders or shares, whatever request they send. They can only change what belongs to them alone: their profile, their sign-in security and their favorites, and only on what they can read.
- Every access is recomputed on every request by a single resolver (`server/domain/access.ts`), covered by unit and integration tests.
- Active content (HTML, SVG) never runs on the application's origin. HTML pages are served from a separate origin, in a CSP sandbox, without cookies.
- Mutations require the application's `Origin` header (CSRF).
- Share tokens are hashed in the database and sealed with AES-256-GCM; passwords are hashed by Better Auth (scrypt); passkeys and TOTP are available.
- Files are stored under keys generated by the server, never under the name they were uploaded with.

Known limitations are listed in [docs/decisions.md](docs/decisions.md).
